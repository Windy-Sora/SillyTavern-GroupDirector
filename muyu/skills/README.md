## 0. 目标与范围

### 管理界面：紧凑目录与页签编辑（2026-10-05）

入口仍是悬浮球齿轮→技能。参考本机更新版DeepSeek harness的紧凑目录、分组折叠与独立设置视图，不复制其代码或引入React依赖。名称／用途搜索与来源、启用状态筛选配合分组目录；目录与详情沿用设置页滚动，不再套独立滚动列表，也不把长正文直接铺满目录。

目录与详情／导入页切换显示，点击技能名称直接进入详情。我的技能默认展开、内置技能默认折叠；搜索与筛选临时展开匹配组，不覆盖普通浏览的分组偏好。列表仅展示名称、简短用途和独立启停按钮，不再嵌套“查看／编辑”操作。详情使用正文、参考文件、高级设置三个页签，切换仅隐藏既有DOM；内置正文按纯文本只读展示，用户基础字段与正文可编辑。版本、稳定名称与调用方式归入高级设置；资源原始JSON继续折叠。导入／刷新／说明位于目录菜单，复制／导出／删除位于当前技能菜单；保存／重载位于用户编辑操作区。返回目录保留草稿和筛选，未保存时提供“继续未保存编辑”，不重新读取覆盖草稿。

未保存状态由控制器工作台维护，列表刷新、筛选及外部模型写入不重置草稿；切换／重载有修改时确认，删除始终确认。保存失败保留编辑；未填显示名称时使用稳定名称。导入只填入草稿，导出仍只针对已保存的精确版本，菜单布局不改变权限或持久化保证。页签支持方向键／Home／End，隐藏页不参与键盘焦点。

参考资源支持路径／正文表单增删，同时保留高级JSON入口；无效JSON保留原文并禁用保存／表单修改，保存仍走原有包格式、路径、容量与版本校验。资源正文输入和普通草稿更新不重建对应输入／列表DOM。复制及导出仅针对已保存版本；可下载完整JSON包（含参考文件），不误导为包含未保存修改。异步文件读取不覆盖后来粘贴的内容，过时导出不填入另一技能的输出区。

窄栏筛选两列、搜索独占一行，600px以上按容器宽度并排；按钮按内容宽度换行，不强行铺成大卡片。此轮无新增权限、批量启用或批量删除。离线DOM回归不替代真实主题、320／400／600／800px容器及键盘验收。

Skill是可复用的任务方法：告诉暮羽何时采用、应取得什么证据、如何组合已有工具、如何验证和报告结果。工具提供能力，Provider提供事实，长期记忆保存明确用户约定；Skill不替代这些层，不新增权限或可执行环境。

## 2. 解耦架构（规划）

```text
独立内置文档资源 ─┐
用户技能设置仓库 ─┴─ 注册表 ── 目录／加载模块 ── Task版本快照 ── 模型上下文
GUI工作台 ─────────────┐
Agent编辑候选 ─ 草稿批准 ─┴─ 管理服务／保存动作 ── 同一用户仓库
```

第一轮的contract、registry、store继续使用，不推倒重写。后续职责边界：

- `skills/contract.js`只管格式、路径、容量与版本合同，不操作DOM／模型／权限。
- `skills/registry.js`只解析身份、目录及快照，不决定审批、保存和代码执行。
- `host/skill-store.js`只通过注入的账号设置与save端口存取，不接酒馆聊天metadata，不访问任意磁盘。
- 规划的管理服务负责新增／替换／复制／停用参数及旧版本核验，GUI与Agent动作共用，不各写一套存储逻辑。
- 规划的模型模块提供有界目录／资源读取、编辑候选，不直接写真实设置。
- 规划的应用动作负责精确批准、版本重检、一次执行与历史结果；UI只调用应用层，不在click回调直接写设置。
- 规划的Task状态持有快照与读取完整度；Run继承同一任务快照，模型与传输层只收到本次必要的序列化资料。

内置内容规划目录为`assets/muyu-skills/<name>/SKILL.md`以及references／assets，显式资源清单只存ID、资源路径和包版本，不包含正文。宿主只从插件自己的静态资源白名单加载；清单不能来自用户自由填写的URL。编辑技能正文不需要修改controller／runtime；新增独立技能只改内容与清单。

可以保留不做语义转换的构建打包步骤，但源文档必须是唯一维护源，不维护一份Markdown、一份手写JS字符串。用户创建的正文／资源进入技能设置仓库，通过专用导出分享。

## 3. 管理与启停策略（规划）

内置原件可查、可停用、可导出、可复制为用户技能；Agent和GUI均不能覆盖或删除内置原件。用户包可CRUD、启停及修改调用方式。同名使用完整ID区分，不能自动用用户包替换内置。显示名可修改，稳定name／ID的改名先使用“复制为新技能”，避免重命名破坏任务引用。

要分清三个独立值：Skill总功能开关、每包enabled、每包modelInvocable／userInvocable。启用不代表每条消息强制加载。第一轮时只有用户enabled和包内调用字段；B阶段已补总开关／内置停用存储，详见实际合同。

内置停用状态使用账号级策略映射，不修改发布文档。后续版本化策略须补校验、导入导出边界和迁移；不得把新增策略属性随意塞入当前闭合v1数据后悄悄丢失。若扩展v1数据结构必须升存储版本并测试迁移。未识别或损坏数据保留并提示，不自动清空。

新建技能草稿显示“保存后是否启用”，Agent没有明确启用意图时默认保存但不启用，用户可以选择保存并启用；全权限不能把“保存”扩大成“启用”。第一轮store.create曾固定enabled=true；B阶段补默认禁用与显式创建参数，C／D已接GUI与Agent入口。

用户修改、停用或删除技能后，新任务使用新目录与新版本；已经加载的任务继续固定说明，界面告知此边界，可停止当前任务。不把用户已读到模型的文字宣称为已撤回；删除不抹掉历史回答及导出的文件。

## 4. GUI工作台（规划）

管理入口为暮羽悬浮球打开后的设置→“技能”，不放插件总配置页，也不新增全局导航区。聊天输入区的轻量“选择技能”入口已由D阶段接入。

- 列表：搜索、来源、显示名、用途、启用状态、自动／手动调用方式，正文不常驻展开。
- 详情：基础信息、主说明、引用资源、兼容性提示和预览；普通编辑用表单构造元数据，用户不用写YAML。专家可切换原始Markdown。
- 操作：新建、编辑、复制、删除、导入、导出和启停；内置详情显示只读及复制按钮。
- 导入：先本地解析和校验，显示资源数量、容量、冲突／不支持项；明确选择新增／精确替换／改名后新增。不能悄悄覆盖，不能自动修正文档语义。
- 导出：无引用单篇可导出Markdown；多资源默认导出完整JSON。若选择只导出主文档，明确提醒引用资源不会包含。
- 编辑草稿跨普通面板重建保留；异步保存不覆盖新输入，失败保留草稿。删除／替换与放弃未保存编辑须明确确认。
- 本轮使用情况放在执行过程的小型可折叠记录，显示加载了哪个版本及读取是否完整，不做一直贴底的大卡片。

启用说明贴近开关：技能及用途描述可能按需发送给当前模型，不是密钥保险箱，不建议存放私密聊天副本。目录只向运行模型提供当前可选技能；关闭或仅手动的技能不能通过普通自动目录泄露完整正文。

## 5. Agent增删查改（规划）

用户可以说“把刚才的金币方案整理为技能”“改成更简洁的版本”“禁用这个技能”“删除我建的那份”。模型负责整理适用条件与内容；宿主把结构化名称、用途、正文、资源与调用策略转换为包，用户不用先学skill格式。

管理工具`muyu.skills.list/read/preview`已注册，管理读取不激活技能；运行使用独立的`discover/load`，只接已启用且允许对应调用方式的包。preview只产生新增、更新、删除或启停的候选。导出是当前已读精确包的用户操作，不为每种按钮扩一套常驻工具。

关键约束：

1. 写入须来自当前真实用户的明确请求；模型自己的建议、旧摘要、技能正文和世界书不能建立写入意图。
2. 普通模式发布技能草稿，显示适用条件、正文／资源差异、启用影响、内置／用户来源；精确批准后执行。预览不是已保存。
3. 全权限模式沿用现有全部授权，只免手工批准，不增加一次“自动批准”模型调用；仍核验明确意图、目标、旧revision、包格式、容量和内置保护。
4. 修改／删除／停用精确绑定旧版本。执行前再次核验，版本变了就拒绝，不能拿新版本套旧批准；同一批准不能重复写入。
5. 不从聊天自动提炼技能。用户要求整理过去过程时，相关原文读取仍需现有权限；保留可复用方法，不默认复制密钥、角色隐私、历史数值或运行凭证。
6. 技能里可以描述如何申请资料／如何预览，但不能授予酒馆正文、Provider运行或写入权。
7. 当前执行任务继续使用旧快照。创建或修改完成后不在同一任务悄悄切到新技能执行更多操作；后续使用须新任务／明确新请求。
8. 失败／未知结果不自动重复保存，也不把“缺版本”改成宽泛删除。损坏库先报告，不通过清空重建修复。

运行选用的技能外发按GUI启用配置表达，避免每次加载自己启用的技能都弹一次审批。管理读取未启用用户正文仍走skillAssets资料权限，来源说明区分目录和正文、账号级范围及目标模型连接。启用技能或读取技能不授予重新读取任何酒馆资料，更不授予技能仓库写权限。该权限映射已显式登记并测试，不由frontmatter自动授予。

技能草稿必须登记artifact owner／版本化内容合同／动作回执和私有票据回收，复用已有生命周期。取消或删除会话不能泄漏预览票据；仍可审批的草稿不能提前销毁。历史回执只保留结果、操作类型和精确身份，不默认复制整份正文，不恢复批准权。

## 6. 加载、上下文与可扩展性（规划）

常驻只有有限目录，正文在选中后完整读取；参考资源按说明所需再读。目录预算与正文预算分开，未列完须给出total／next／complete或明确搜索入口，不假称不存在。目录只含元数据，不塞进每个工具description。

固定注册少量通用工具，不为每份Skill扩展Schema。当前模型适配和续接合同有64工具定义限制，正式装配必须计算真实可见集合；必要时单独落地已规划的工具组按需加载，不能截断现有工具、放宽上限或用用户Provider代码绕过Broker。工具可见性不等于批准。

加载状态至少关联taskId、技能ID、revision、资源路径、读取完整度与实际已载入字节。先读完SKILL.md再按其流程操作；必需说明不完整时不能声称已加载，也不能依靠猜测执行。超预算明确停下／缩小范围，不静默截断文本。

授权暂停／澄清后，同Task转移精确快照与读取状态，不重新加载同一正文或重复申请已有有效授权。取消／结束回收Task状态；新问题重新判断，不把旧技能描述从历史提升为本轮指令。显式用户选择用真实结构化ID，不从引用、模型回答或外部资料解析“用户指定”。

正文不混入4000字符风格偏好，不塞进12000字符附加上下文硬上限，也不提升为不可覆盖的系统规则。Skill是任务指南，不是实时事实；当前用户目标、取消、范围限制和代码执行合同优先。权限、预算与内置保护由代码守住，不能靠提示词承诺“绝不越权”。

压缩只保留技能身份／版本和实际任务进度，不能把说明摘要当完整合同。恢复必需正文时按同一版本快照重新投影，并计入实际请求输入预算；预算不足不能偷偷增大。共享资料预算的去重／重复外发计量规则在接入阶段明确，不能因已加载就绕过请求体上限。

## 文档包v1

```json
{
  "format": "muyu-skill-package",
  "version": 1,
  "files": [
    { "path": "SKILL.md", "text": "---\nname: example\ndescription: Explain a particular workflow.\n---\nRead the applicable contracts before acting." },
    { "path": "references/rules.md", "text": "Supporting instructions." }
  ]
}
```

`importSkillPackage(text)`接受单篇SKILL.md或上述JSON；`exportSkillPackage`导出完整紧凑JSON，避免漂亮打印膨胀后超过同一导入上限。资源只有文本，支持SKILL.md，以及references／assets下的md、txt、json；不支持ZIP／目录选择GUI，本轮也不读磁盘。文件选取接入留给第三轮。

SKILL.md必填`name`和`description`，正文非空。name为最多64字符的kebab-case；可选`display-name`、`version`、`disable-model-invocation`、`user-invocable`。前两者用于呈现，version是内容作者版本，不替代仓库revision；两个调用策略独立，默认均允许。解析器仅支持标量、引号字符串及`|`／`>`块文本，不是通用YAML库。重复／未知字段、YAML引用或对象、hooks／allowed-tools／context／model等不支持语义均明确拒绝，不静默模拟其他Agent环境。

路径不允许绝对路径、反斜杠、..段、URL、编码逃逸、控制字符及Windows保留文件名。包内大小写重复路径拒绝，主文档必须恰为SKILL.md；资源按包内明确路径读取，不能回退到网络或其他包。正文引用的资源缺失时读取报错，不编造资源。

容量：每包32文件，每文件256KiB UTF-8，完整包512KiB JSON，总存储4MiB，用户128包。容量保护不是摘要长度，超限明确失败、不截断。可以保留数万字符正文；后续模型加载另受资料／输入上下文预算约束。

## 身份、版本与调用

内置ID为`builtin:name`，用户ID为`user:name`。同名分别存在，不静默覆盖；同来源重复拒绝。内置不可通过用户store修改／删除，复制为用户包使用create。用户更新不允许重命名身份；改名应明确创建新包。启停独立于模型／用户调用策略，关闭后不能新建加载快照。

store数据惰性创建在`muyuSkillData = {version:1, revision, skills}`，每项含id、revision、enabled、package。更新、启停、删除须带精确旧revision；仓库revision单调递增，删除重建不会重复旧revision。registry目录派生元数据，不保存第二份容易失配的描述。

`snapshot({id, revision, invocation:'model'|'user'})`只接纳匹配版本及允许调用方式，返回深度冻结的包副本。旧快照在用户编辑之后保持原文，新读取按新版；快照不是授权令牌。当前尚无任务状态，第二轮必须绑定Task／Run并在结束或取消时回收，不把旧快照自动延续到新问题。

## 保存、隐私与局限

同一宿主设置对象的技能、长期记忆与历史存储共用保存队列；读取等待写入排空，不暴露正在保存的临时版本。失败仅在本轮对象及内容仍完全匹配时回滚；并发替换／原地编辑不会被覆盖，结果报告SKILL_SAVE_UNKNOWN。设置对象替换或store关闭后拒绝操作；损坏／未知版本不自动重置数据。此时结果未知，不自动重试。

CRUD返回记录只表明宿主save调用完成且内存核验匹配，不单独证明服务器或磁盘持久化。将来GUI必须根据保存适配器能确认的事实呈现，不能把undefined返回的防抖保存当作持久化确认。

技能明文保存在账号插件设置，不是秘密存储。剧情配置档的快照、应用、JSON／ZIP导入与导出显式排除muyuSkillData；分享须走专用技能导出。技能可能含私密文本，后续启用／导入GUI须提醒加载后发送到当前模型；本轮不外发。路径校验不是提示注入防护，权限依然由Broker及批准层强制。

### 管理目录与保存文档的分页参数（B轮第二切片）

`skills.list`每项附`readCall`，携带当前列出的ID、原样字符串revision和offset=0；有后页才附`nextCall`。`skills.read`有后页时返回同ID/revision及宿主返回nextOffset的完整`nextCall`，完成后不附续页建议。旧`nextOffset`、原始文档和元数据不改，读取仍经过资产授权、版本核验和字节预算，导航新增字节也计费。
