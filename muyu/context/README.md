# 上下文工作台（阶段 3）

当前大窗口实现、容量和未完成边界见 [50 万工作上下文](LARGE-CONTEXT.md)。

## 架构与边界

原始会话与模型上下文是两份不同数据。会话消息不因截取/整理删除；摘要是带来源检查的派生参考资料，不是系统指令、权限、宿主最新事实或任务检查点。

本地 `codex-main/codex-rs/core/src/compact.rs` 与 `context_manager/history.rs` 仅用于学习：借鉴上下文视图与记录分离、独立压缩步骤、来源版本/取消边界。没有复制 Rust 实现、提示词或引入 Codex 服务依赖。暮羽不实施运行中压缩。

| 文件/层 | 职责 |
| --- | --- |
| `policy.js` | 闭合配置、JSON 字节统计、保守 Token 估算和安全投影 |
| `planner.js` | 完整问答选取、摘要来源检查、连续分段整理候选 |
| `compaction.js` | 无工具摘要请求与有界响应解析，不拥有存储或权限 |
| `composition.js` / `core/runtime.js` | 组合层注入上下文端口；内核仍只导入 core 文件，负责同一调用/时间预算、每请求检查、取消和物理 drain |
| `model/chat-completions.js` | 统计最终适配后的 payload，包含实际工具定义及私有思考回传；网络前再守卫 |
| `application/controller.js` | 会话归属、授权、发送时快照、手动整理、摘要写回 |
| `sessions/` | v3 可选摘要随原始记录一起保存，摘要不进入索引 |
| `ui/context-view.js` | 配置、估算/实测区分、查看/清除摘要、整理确认 |

## 设置与用户入口

后续行为偏好已接入：正式请求的系统指令纳入估算和字节总量，单列 instructionBytes；不能被历史裁剪删除。摘要请求不携带行为偏好，具体见 [指令合同](../instructions/README.md)。

齿轮 → 上下文预算。插件设置 `muyuContextConfig` 排除在剧情配置档之外。

- `inputTokens`：新安装默认 `900000`（本地估算 Token），面向 1M 模型保留输出与估算余量，但不保证一定符合服务商窗口。未标记的旧完整默认组合（32000或500000、recentTurns=12、autoSummary=false）读取时升级；其他组合及 `null` 保留。明确保存后写入 `muyuContextBudgetVersion`，即便设置成旧默认值也不再升级；历史上与默认完全相同的手动设置无法区分。可选 `null` 不按估算 Token 拦截，仅受 8 MiB 请求体安全上限保护。手动模式支持 4096–1000000，估算不是实际模型窗口；小模型需降低预算，增大预算可能增加费用。
- `recentTurns`：1–24，默认 12。只作为整理时保留近期原文的参考值（最多两轮），不再限制正常请求的历史轮数，也不再单独触发整理。
- `autoSummary`：默认关闭。仅在用户发送且旧历史未被上下文覆盖时尝试；打开面板/浏览历史不调用模型。

聊天区“上下文”提供计划携带轮数、未覆盖消息数、历史部分估算、最后一次请求计量及摘要查看。计划不是最终请求；适配器检查仍可能减少旧历史，实际保留条数单独显示。运行中修改设置只影响下一次发送。

“本次不携带旧历史”只跳过旧对话和摘要，不删除原文、不撤销工具授权；成功入队后自动复位，不与已有配置草稿续改组合。手动“立即整理历史”须再次确认外发，沿用已有连接和相关资料授权。

## 输入计量和裁剪

无新增 tokenizer 依赖。Token 估算使用序列化 UTF-8 字节数 / 2 向上取整，是偏保守的启发式，不能保证等于任何模型实际分词。输入预算与最大 8 MiB 请求字节保护并用。

历史规划上限为 min(输入预算或请求字节上限/2, 请求字节上限/2) 的 90%，预留 10% 给当前问题、指令、工具及后续结果；不是模型真实余量。预算内按完整成功问答尽量保留全部原文，不按固定轮数截断。模型第一次正式调用前，无有效摘要时可继续移除完整旧问答；有效摘要及其连续原文尾部不裁剪，放不下以 `CONTEXT_INCOMPLETE` 停止。当前问题、任务约束和本轮工具调用不裁剪，其他输入超限以 `CONTEXT_LIMIT` 停止，绝不破坏工具配对或移动私有思考缓存索引。

消息、工具定义、工具结果、思考回传字节是序列化分项，存在包含关系，不能相加当总量。服务商报告的实际输入/输出 Token 仍见本轮开销；缺失报告显示未知，不当作零，也不从字节数伪造实测。摘要调用的实际用量可单独查看，并包含在总量内。

## 整理规则

每次最多整理一个连续历史段；手动模式下候选请求不超过估算输入预算的 98%，自动模式下不超过请求体安全上限的 98%。保留最近至多两轮（受近期轮数设置限制）。有有效旧摘要时，合并旧摘要与下一段完整问答，来源指纹仍覆盖原始记录的整个前缀。单条超长消息会分段传给摘要模型（普通模型文本上限为 2 MiB 序列化 UTF-8，工作消息上限 4096，历史规划预留 256 个消息槽位给本轮轨迹），但候选超出上述上限时不会跳过前缀；一次整理不保证覆盖全部旧历史。滚动摘要可能损失细节，原文始终可查看/导出。

摘要调用无工具，初次输出预算为 min(4096, 用户单次输出上限)，最终文本不超过 6000 字符；不接纳工具请求或未完成响应。自动整理仅在输出截断、尚有调用/时间预算且可提高输出上限时重试一次，重试上限为 min(8192, 用户单次输出上限)，使用新的私有模型上下文，至少预留一次正式回答调用。两次共用整理子步骤截止时间，手动整理不重试。不会回放旧工具调用或隐藏思考。

使用有效摘要时，必须携带其覆盖前缀之后的全部原文，不受 recentTurns 窗口裁断；来源覆盖与原文尾部之间不得有缺口。无法完整携带时标记阻塞；整理失败或因预算跳过时以 `CONTEXT_INCOMPLETE` 停止，不能发送旧摘要加不连续近况。成功的部分整理也保留完整剩余尾部，最终请求计量不得再次裁剪这份受保护历史。可以继续手动整理、增加预算，或由用户明确选择本次不携带历史；原始会话记录始终保留。

第二轮覆盖状态：规划器提供闭合计数 `total/summarized/raw/omitted/excluded` 与 `complete/window/blocked/omitted` 状态，所有分类合计必须等于原始消息数。`summarized` 表示摘要来源覆盖的原文条数，不是摘要质量保证；`excluded` 单独表示授权或用户主动排除，不能当成预算缺口。运行记录只投影计数和 planned/skipped/summarized/fallback/blocked 状态，不存正文、来源指纹、密钥或任意错误文本。界面分开显示当前发送计划与最近任务的恢复/阻塞结果，不自动增加预算或勾选不携带历史。

摘要候选以完整问答作为结束边界，但连续前缀内夹有失败/取消的原始消息时也必须携带，不能把未读原文算入摘要覆盖范围。授权等待后的在途工具续接不重新整理历史，不改变已有工具配对或私有思考索引；仅新任务可按当前设置重新规划。没有新增存储字段或数据库迁移。

- 自动整理计入本轮模型调用数与总超时；调用预算小于 3 或总超时不超过 10 秒时跳过。整理子步骤最多占总超时的 1/3，且不超过 30 秒。
- 手动整理是单独任务：最多一次模型调用、最多 30 秒（不超过运行超时配置），无工具，也不生成伪造用户/助手消息。
- 普通模型/解析失败：原文和旧摘要不变；存在旧摘要时只能回退到旧摘要加完整未覆盖原文，放不下则停止。没有有效摘要时保持原有近期完整问答窗口；无无限重试。摘要用量展示实际调用次数及已报告 Token 合计，缺失报告不伪造成零。
- 取消、超时：不再发起后续请求；等待物理 drain 后才能释放运行槽。部分流、迟到结果不提交摘要。
- 写回检查原会话、当前聊天/全局范围、相关授权及来源指纹。重命名不改变摘要来源；切聊天、删除、撤权不能让迟到结果污染会话。

## 存储与兼容

记录版本及 IndexedDB 版本升级为 3，数据库名仍为 `gd-muyu-history-v1`。不删除 v1/v2 数据，读取时补 `contextSummary: null`；旧客户端不能以更低数据库版本打开后覆盖新记录。

摘要字段固定为 `through`、`fingerprint`、`text`、`createdAt`。fingerprint 是非加密变更检测，不是签名或授权依据；摘要本身始终不可信。消息变更导致来源不匹配时不使用摘要，界面标注失效。

摘要保存/清除沿用会话自动保存开关：关闭时只改本页工作副本，不暗中落盘；若磁盘已有旧版本，刷新可能重新读到它。JSON 导出包含摘要和原文，Markdown 保留原始问答。导入生成新只读记录，摘要不能解锁执行。授权从不随摘要持久化。
