# 配置草稿单次应用

当前操作协调器同时支持旧 memory-config/v1 和 settings-config/v2。新领域使用相关叶字段及语义依赖核对，不覆盖无关并发编辑；回执支持版本化长文本。领域清单、容量与保存限制见 [配置契约](../config/README.md)。

统一入口更新：配置预览不再让用户预选字段；可用范围仍封闭为下述四字段，模型须仅提交用户明确要求的差异，意图仍需人工复核。首次预览在 source:memoryConfig 授权检查通过后才读取基线、绑定草稿。普通问题不绑定草稿、不读取设置。读取授权不替代逐份写入确认；统一会话回执使用 DTO v5，旧分类 v4 兼容保留。

首版只支持现有 memoryEnabled、autoMemoryEnabled、autoMemoryInterval、autoMemorySpeakers 四字段。模型工具仍只读/生成草稿；没有注册通用写工具。用户必须在当前配置草稿上选择“查看并应用”，再点击“应用这份修改”。自然语言同意及读取授权不批准写入。

## 准备、批准、执行

- config-apply.js 保存连接内的不可变操作副本：操作 ID、artifact ID/revision、session、全局所有者目标、原基线和具体差异。界面只提交操作 ID，不能改写目标或修改内容。
- 准备及批准均调用原草稿重新校验，再在实际执行前核验。修改草稿、删除草稿、基线变化后不执行旧批准。操作先进入 applying 再调保存，重复点击不执行第二次。
- config-write.js 在同步的基线检查与四字段修改间不 await；仅修改 diff 中字段。无默认值填充、前置开关自动补开、全设置快照恢复。
- 当前配置是全局配置，影响所有聊天。启用自动功能可能影响后续生成与费用。切换酒馆聊天不改变其全局所有者，但从其他暮羽会话不能批准此操作。
- 重连/禁用等待进行中的保存结束并清除操作；归档/删除使等待批准失效，保存中不允许这些管理操作。刷新不恢复批准。停止仅使待批准操作失效，不声称可以取消已经发出的保存。
- 最多64条连接内操作。同一草稿版本处理后不能重试；需重新生成预览。记录留有原始前后值及结果；不持久化操作或审批，不提供自动重试/回滚或一键撤销。

## 保存结论（本地 release 核实）

SillyTavern public/script.js 的 saveSettings 会在未就绪时安排重试并返回，在保存失败时捕获异常；成功后发送 SETTINGS_UPDATED，但该事件无请求 ID。插件 saveSettingsConfirmed 使用全局事件观察，不能在其他保存并发时证明某次操作已落盘。

因此本轮接入现有官方保存链路，但不将其 undefined 返回或全局事件视为本操作的确认凭据。正常返回、异常均保守报告 applied_unconfirmed，异常另标 saveError。仅未来可信且能关联本次操作的 host receipt `{confirmed:true}` 才可报告 applied_confirmed。当前真实宿主适配路径不会生成该凭据。

状态：pending、applying、cancelled、expired、not_executed、applied_confirmed、applied_unconfirmed、outcome_unknown。保存期间再次编辑或设置对象替换会标 changed，不恢复旧快照覆盖后续修改。异常文本不进入结果，失败不等于磁盘或内存未改变。

## 操作回执与解释

终态操作产生独立、只读回执：操作/草稿版本、时间、提议差异、执行状态、保存异常与并发变化标志。回执绑定原暮羽会话，不插入伪造的 assistant/tool 消息；切页和面板重建不再次执行。应用卡及会话回执使用同一事实投影。提议值不证明批准或执行成功，历史结果不代表当前配置。

回执写入会话 DTO v4，旧 v1–v3 仍可读；每会话最多64条。只在开启历史保存时持久化，JSON/Markdown 导出保留事实，导入只读且不能恢复审批。历史保存失败与配置应用结果分离；重试历史保存不调用配置写入。记录容量失败时保留连接内回执并提示用户复制，不将记录失败改写为业务失败。

模型上下文最多携带当前会话最近3条回执，需诊断资料授权并满足原历史权限；“不带历史”排除回执。通过独立 applicationContext 数据通道进入协议兼容的 user 消息，不写入普通用户正文、不伪造 tool_call_id，也不提升为系统指令。正文摘要不替代这份有界事实，实际请求开销计入既有预算。

“让暮羽解释结果”是显式、独立的只读模型请求，工具列表为空，不绑定配置草稿生成器、不发布新草稿，不清空输入草稿。解释失败/取消可以重新请求，但不能重跑配置应用；显示的解释状态不改变操作回执。导入或归档会话不提供此按钮，恢复历史也不自动请求模型或恢复授权。

解释请求使用独立任务规则，不复用普通聊天的 Provider 选择器指南。模型投影显式解释 changed 是保存等待期间的后续变化/对象替换/核验警告，不是本次是否修改成功；未知结果中的 false 标志可能仅表示未获得结果。saveError 不推翻已经发生的内存赋值，草稿 revision 也不是当前配置版本。仅增加有界派生说明，不改变存储 DTO、权限或执行行为。

## 执行保证边界

回执新增“核对当前配置”：独立本地只读任务，经统一Provider v2读取memoryConfig，只比较该回执提议的字段。需要diagnostics授权，不调用付费模型、不生成草稿、不重复应用。展示的是新读取时点的内存值；即使一致也不证明原操作落盘。核对结果不改写历史回执、不持久化；原“让暮羽解释结果”继续只解释历史。详见 [Provider合同](../modules/providers/README.md)。

默认呈现收敛：简单追问先给结论，仅补必要提醒；不默认重复内部ID、时间戳和整份合同。明确肯定当时内存赋值，同时保留持久化不确定性。配置草稿说明现有“查看并应用 → 应用这份修改”人工路径，不把用户按钮操作描述成模型能力。完整回执只在会话回执区展示，草稿卡保留原差异和指向结果的提示；解释状态中英文显示，与按钮分行。没有回执的异常分支仍保留原结果提示，不因此隐藏执行状态。

只保证本实例重复批准不重复执行，不承诺跨标签页互斥、服务器 CAS、跨刷新 Exactly Once 或可撤回已发送请求。未修改宿主核心，不绕过宿主保存接口。对既有普通 UI 保存、自动生成副作用不提供事务保证。

测试覆盖仅预览不写、伪造/重复/过期批准、基线与草稿变化、写入前再次检查、同步/异步保存异常、并发编辑、重连 drain、中英文确认及面板重建。确定性测试不代表真实宿主视觉验收。
