## 2026-10-06 C第四切片第三轮：读取证据与整单子步骤关联

新增`task-read-evidence.js`，只捕获已校验工具结果的历史元数据。宿主生成`read-evidence:` UUID，区分目录、合同、实际读值、空结果、正文页与失败；不复制Provider正文、原值、查询参数或代码结果。最多32条元数据、128个run/call去重身份，满额停止新捕获并明确标记；旧记录不代表最新状态。元数据只存在连接内Task，不进入公开snapshot、聊天历史、摘要或持久化。

可选应用port注册`muyu.task.bind_read`：模型显式提交当前已批准读范围方案的精确版本、宿主read步骤ID和已观察证据ID。关联和每次模型投影都复核原工具的当前来源权限，异常或非明确true拒绝；不会申请新来源、重新读取、授予权限或完成分析。目录和合同即使关联到读取步骤，也仍保留原类别，不能算成实际读值或全来源读齐。方案替换／删除让旧关联stale，新Task、目标／会话／连接清理不继承。

`task.preview`新增可选`steps`输出，为每个实际候选子步骤返回不含业务身份的ID、kind和displayIndex。模型通过`task.bind_step.bundleSteps`显式映射到同方案的variables／settings／code步骤；每项也必须出现在stepIds中。重复子步骤、伪造ID、类型不符、候选不唯一或归属过期拒绝；不根据标题、名称或相同kind猜映射。旧草稿和未提供子映射的子步骤继续unmapped。

发布时核对候选观察的完整布局与精确草稿版本，首次审批观察冻结映射。V4/V9回执须通过原回执合同，再逐项核对私有业务身份与规范顺序；布局不符只保留操作总状态并标layout-mismatch，不挂子回执。实际子步骤保持confirmed／unconfirmed／partial／unknown及保存域分离；只有显式映射项携带proposalStepId和bundleStepId。旧版本失效同步标stale，不重绑或重放。映射仍是model-proposed、intentVerification=not-assessed；提案步骤及目标完成仍not-assessed。

本轮补的是精确身份关联，不是GUI进度、意图充分性判定、分析完成证明、通用Provider正文跨段缓存、依赖调度或刷新恢复。下方第二轮“read和子步骤未实现”为当时范围，本轮仅补上述路径。

验证：新增6项读取证据、5项整单子步骤边界及1项生产controller集成。全量3256项（3255通过、1真实宿主跳过），静态与17/17历史BUG合同通过。DeepSeek合成宿主六请求，两个bind_read及一个bind_step均实际返回bound=true，整单子步骤使用宿主返回ID，未批准写入、宿主未改；不是真实GUI／ST验收。工具结果在后续请求反复出现，不能将重复观察计为额外关联调用。

## 2026-10-06 C第四切片第二轮：显式步骤／候选／草稿绑定

新增`task-step-bindings.js`，仅controller组装关联port时提供`muyu.task.bind_step`。模型提交当前方案artifactId＋revision、宿主稳定stepIds及成功preview的candidateId；宿主核对同Task／session／target／活跃run、方案已发布且读范围已批准、步骤存在且类型匹配、候选确在当前intent中且只有唯一来源工具，并且broker已观察到该成功候选。工具只记录关联，不读取宿主、不批准或应用，不判步骤／目标完成。

首批支持config.preview／settings.preview→settings步骤、variables.preview→variables步骤，以及task.preview整单→显式列出的settings／variables／code步骤。整单绑定是整份草稿与步骤集合的模型提案关系，不自动把回执子步骤的序号或kind映射到提案步骤。read／analysis、其他资产预览及生成工具本轮不绑定。不根据标题或语义自动兜底。

最多128个成功候选观察身份、32项关联；重复run/call不覆盖，候选ID重新生成时删除旧关联。观察容量耗尽清空关联并停止捕获，不能用旧候选身份挂接后续草稿。相同关联重复可幂等，不同步骤／方案的静默改绑拒绝。发布后须核对候选仍唯一、tool归属和Task/session/sourceRun及草稿kind；再固定artifactId＋revision。关联不进入草稿内容／存档，只存在连接内Task。

审批操作首次观察时携带精确草稿关联，投影stepMapping=explicit-model-proposal及stepReference（plan版本、stepIds、草稿版本、model-proposed、intentVerification=not-assessed）。旧绑定因方案替换／修订、草稿修订／删除而stale；已有操作仍保留原历史回执，不重绑或重放。真实操作状态与提案步骤完成不同，提案step.status及goalCompletion仍not-assessed；不能以精确ID关联证明内容满足用户目标。

集成验证同时修正旧基础记忆预览的续接：task-plan不是config-draft，不能传作previousArtifact；继续编辑真正的config-draft仍保留。没有扩大审批或保存权限。下方首轮“未映射”为当时范围，本轮只补上述显式路径；GUI进度、内容意图核验、read步骤证据及子步骤语义映射仍未实现。

验证：10项绑定边界与1项controller规划→草稿→关联→人工批准集成回归；全量3244项（3243通过、1真实宿主跳过），静态及17/17历史BUG通过。DeepSeek最终六请求实际返回bound=true，未批准写入、合成宿主未改；有一次读取参数纠正及内部码表达残留，不宣称完整复杂任务／GUI验收。

## 2026-10-06 C第四切片首轮：Task／草稿版本／实际操作回执关联

`task-operations.js`由Task持有者观察生产审批coordinator，不是执行器。controller在现有actionChanged中接入pending、applying与已有validateReceipt通过的终态。首次关联核对Task、session、已登记sourceRun、action目标与草稿版本／内容；模型文字、外层tool成功、新Task或导入存档不能建立关联。不新增工具／批准／重试，不改变保存合同。

按operationId去重，最多32项；仅投影草稿身份／版本／类型、历史状态、回执时间及当时方案引用，不复制diff、代码、名称或业务值。终态投影前复核原回执来源授权，非明确true不外发；私有权限描述只保留来源及必要的裁剪chatKey，不缓存完整回执。pending不等于已派发，applying不等于完成，confirmed／unconfirmed／partial／unknown保持分离。终态不被后续重复通知改写，applying不能退回pending；目标完成仍not-assessed。

当时方案引用固定artifactId＋revision，新方案、修订或删除令旧引用stale，不重绑到新版。已绑定操作在草稿修订／删除后仍可接收原操作身份的最终回执，保留历史结果。取消Task不把applying改为cancelled，不证明回滚或中止；容量回收保护pending/applying操作所在Task，物理清理后不恢复或重放。

**规划步骤尚未精确映射。** 现有task-plan只给类别及文字，无可校验的操作关联键，因此stepMapping明确unmapped，不用相同kind／顺序猜步骤。V4/V9整单回执的实际子步骤按operationId＋回执序号生成稳定身份，保留kind／status／chatSave／settingsSave；它们不是task-plan的提案步骤，不把实际子步骤状态转成提案完成。其他回执版本只投影操作总状态。后续需要显式提案步骤→候选／草稿版本绑定契约，再接GUI进度，不开放任意模型自由绑定。

本首轮没有通用Provider资料续带、业务生成工具的操作回执关联、目标修订、依赖调度、自动重试或刷新执行恢复；不宣称整个C第四切片完成。测试与最终全量记录见优化工作单。

验证：新增8项定向回归；生产coordinator延迟执行一次，任务取消后保留unknown终态且不重试。全量3233项（3232通过、1真实宿主跳过），静态及17/17历史BUG通过。本轮未调用付费模型，也未做GUI验收。容量省略计数表示被省略的通知次数，不是独立操作数。

## 2026-10-06 C第三切片：同任务历史读取结果续带

`read-references.js`提供私有、有界的跨段结果传输，仅接纳已登记字段的settings.read返回与通过结构化合同核验的memoryConfig结果。不接纳任意Provider正文、代码结果、目录、草稿或回执，不拦截后续读取、也不充当读取缓存。当前执行段仍使用原工具结果；仅后续段携带历史参考。

每字段保留最新一次读取结果、GUI中英文名称、来源工具、宿主capturedAt与执行段号；缺失、false、null、空串不同，不补默认。每项最多2048 UTF-8字节，整个字段数组最多16384字节，超限整项省略，不截断值。128个run/call身份去重，达到上限清空并停止捕获、显式标注；新读取失败／不合法／过大时不回退到该字段旧值。

每次模型请求投影前，controller使用原工具的实际读取授权政策核查当前Task／target权限，缺权、异常或异步非明确true均不携带。不自动申请或授予权限。新Task、会话卸载、切换target、连接重建和撤权清理仍遵循持有者合同；值不进入公开snapshot、聊天历史、摘要或持久化。投影仍占原单槽，计入既有输入及请求体预算。

参考明确标为不可信数据、非指令、非当前事实、非持久化证据、非写入基线：可回答“刚才读到了什么”，不能据此回答“现在是什么”或批准修改。长Prompt整项省略，通用资料正文的续带尚未接入。下方C第二切片的数值丢失为历史问题，本切片仅修复上述两类配置读取的跨段路径，不宣称全部上下文恢复或整个C轮完成。

验证：新增6项缓冲／store及1项controller撤权回归，澄清测试验证等待时独立编辑不改写历史值。全量3225项（3224通过、1真实宿主跳过），静态与17/17历史BUG通过。DeepSeek最终三题九请求，两类读取均能在澄清后报出旧值；独立修改题明确区分历史与当前，不重复读取。仅合成数据，不保证通用资料或真实GUI场景。

## 第一切片历史合同

`task-evidence.js` 是应用层组装的只读观察器，不是 Task 的审批、调度或完成状态机。composition 每条新执行轨迹创建独立实例；runtime 在收到 broker 已校验的结果后观察，在下一请求的 taskGuides 中替换投影。不写入聊天记录、历史摘要或持久化设置，不截断原工具结果／思考轨迹，不增加工具。

## 证据边界

- settings.catalog／provider.list 只记录目录查询；settings.contract／config.contract 只记录查询过的合同字段，不计已读值。
- settings.read 按请求、返回字段清单与 values 自有键交集累计观察过的字段；false、null、空串也算返回。缺失不补默认。之后读取缺失仍保留过去观察身份并单列 latestMissing；不能据此判定当前值或成功保存。
- provider.read 只读宿主信封状态与 readHint：失败、空、目录、正文页分开，不解析 text 的指令／伪状态。nextOffset／truncated 只说明本页是否还有内容，不证明全来源读齐。memoryConfig 仅通过独立结构化合同核验后计入四项配置字段。
- 五类配置／变量草稿只记录历史候选身份。errors 非空即拒绝，即使外层 ok；候选不等于已发布产物、当前有效版本、用户批准、应用或持久化。task.plan 只表示提出方案，不证明目标完成。
- 外层失败／拒绝与 effectState=unknown 分开；未列出的工具不作语义判断。真实写入／保存由独立操作回执解释，不由本观察器统计。

## 生命周期与容量

最多接纳128个 runId＋callId 观察身份，保留最近16条结果类别；更早条目计入 omittedObservations。达到容量后停止接纳，不逐出去重身份并重复计账。字段集合限于生产配置注册表；不保留原值、正文、任意错误文本或用户目标描述。不输出“完成步骤数”。

原调用授权暂停的私有 resume 携带同一实例，并核对 taskId；target 仍由原 runtime 续接合同检查。续接只执行待批准调用，不重做前序读取。新轨迹为空；跨聊天原调用续接被拒。实例不进入公开 DTO，随原有 resume 释放／任务结束而失去所有权。

**本切片不提供整个会话的持续进度。** 显式模型权限／澄清交接或任务方案批准重新开段时没有复用此投影；后续需要独立、有界的 Task 状态持有者及对象／修订核验，不能靠历史答案重建执行权。刷新后没有可执行检查点恢复，也未增加稳定步骤 ID、依赖、取消或修订联动、GUI进度卡。

Skill 原投影最多257条，证据另占一条，runtime／模型适配器共同限制258条及原有总消息／字节／输入预算。证据只在正常执行请求出现，计入上下文测量；不扩4000字符基础指令合同，不进入专用压缩请求。
